Lander — Orbiter on PHP hosting

Lander is the Orbiter admin for ordinary shared hosting: PHP 8.1+ and SQLite, no Node, no build server. Same SQL file (.pod — a plain SQLite database, only renamed), same Station interface. Overview page →

When to use it

Orbiter runs on Node. Many hosts (World4You, Strato, IONOS, cPanel) only offer PHP. Lander gives editors the same admin there, while your Astro site reads published content from a live API.

What you get

  • The Orbiter admin (Station mode, themes, dock) as static files, backed by a PHP API with the same paths and JSON formats.
  • Live read API — /api/public/<collection>[/<slug>], CORS for your site's domains and a short cache (10 s by default, public_cache_seconds). Changes appear without a rebuild.
  • Markdown import — .md with frontmatter via Admin → Import or bin/lander import-md.
  • Media as files in public/media/ (JPG, PNG, WebP, GIF, AVIF, PDF, MP3, M4A, WAV, MP4 and more; real file type checked, PHP execution blocked in that folder). Media fields are resolved to {id, url, alt, type}.
  • Music and video — MP3, M4A, AAC, OGG, WAV, FLAC, MP4, WebM and MOV can be uploaded (limit max_upload_mb, 40 for new installs) and are served with range requests. Use a file field and read .url in your site.
  • Made for phones and tablets — dock labels, drawers as panels, list rows with a “⋯” menu and swipes, touch-sized controls, an installable admin (home screen, safe areas). The admin is German by default; change it under Settings → Admin language.
  • Preview — set the meta site.preview (for example {"events": "/events/?vorschau={slug}"}) and site.url; the editor then shows a Preview button that opens the real page, drafts included while you are signed in.
  • Editor role — editors see a short dock and cannot touch schema, users, build or import (the server answers 403).
  • Inbox for form submissions (server-to-server with a form_token).
  • Users — admins add editors and admins in the admin (create, change role, reset password, delete).
  • Install and update — an installer that detects subfolder or domain root, weekly automatic backups, image variants (?w=800&fmt=webp), and a signed one-click update from the admin.

Install

  1. Upload the folder and set the document root to public/, ideally on its own subdomain (the admin uses absolute paths).
  2. Create lander.config.php (public_origins = your site's domain, media_url = full URL).
  3. Make data/ and public/media/ writable for PHP.
  4. Create a user with php bin/lander user <name> admin (SSH), or create it locally and upload the SQL file data/content.pod.

Speed: versioned assets

The admin pages are sent through PHP, which adds ?v=… to scripts and styles; the version changes with every file change. With mod_rewrite and mod_headers those files may stay in the browser cache for a year (public/.htaccess ships the rule). Without them everything still works, the browser just asks again each time.

Connect your site

const events = await fetch('https://redaktion.example.at/api/public/events').then(r => r.json());

At build time (SEO) query the same URL in the Astro frontmatter; at runtime the page is always current.

Backup and restore

Settings → Pod → Backup & restore (admins only). Download the SQL file (.pod, small and fast) or a ZIP with media. Restore takes either one back: the server checks the file (SQLite, integrity, required tables, at least one admin), keeps a copy of the current pod in data/before-restore-*.pod, swaps it in, unpacks media (images and PDF only, real file type checked) and rewrites media paths for the new host. This is also how you move to another host. Limits: max_restore_mb and PHP's upload_max_filesize / post_max_size; put very large media folders on the new host via FTP. Backups contain password hashes, so keep them private.

Sign in with Digi-ID

Under Account → Digi-ID a user links a DigiByte address (the password is asked once). The login page then offers Sign in with Digi-ID: scan the QR code with a Digi-ID wallet and you are in, without a password. The wallet signs a one-time URI that contains your domain; it expires after five minutes and works once. The password login stays as the fallback. It needs a public HTTPS address and the PHP gmp or bcmath extension (with bcmath a sign-in takes about 0.3 s of server time). Legacy addresses starting with D are supported. Details →

Rebuild on publish

Under Settings → Build, enter a build webhook (Netlify, Vercel, GitHub Actions …). Lander calls it with a POST whenever an entry is published. Under Settings → Webhooks you can add signed hooks for publish and delete events: the body is JSON, the header X-Orbiter-Signature: sha256=… is the HMAC-SHA256 of timestamp.body with the hook's secret (shown once). The last 50 deliveries are logged. Each hook gets one attempt; there is no retry queue.

Update

When a newer release exists, the dashboard and Settings → Pod show it with an Update now button. Lander downloads the release ZIP and its signature from GitHub and checks the Ed25519 signature against the public key built into the code. Only then does it replace src/, bin/ and public/; the config, data/, media and the subfolder paths stay. A copy of the pod and the previous code is saved to data/update-rollback/ first.

It needs the PHP zip and sodium extensions and outgoing HTTPS. If something is missing, the admin tells you what, and you replace the files by hand: unzip the release over the install, keep lander.config.php and data/, and run php bin/lander rebase <base> in a subfolder. update_check => false turns the hint and the button off. Updating from 0.3.0 to 0.3.1 is manual (0.3.0 has no button); from there on it is one click.

Where is the update button?

The update line sits at the very bottom of the Pod card in Settings; the dashboard shows the same hint at the top. It always names the installed version. The Update now button appears only if a newer release exists. If you uploaded the files by hand and the line reads your version without a hint, you are up to date and there is nothing to click. Reload the admin with Cmd/Ctrl+Shift+R first, otherwise the browser may still show old files.

No update line at all means the install is older than 0.3.1. Update it once by hand (unzip over src/, bin/, public/; never replace public/media/ or data/); from then on it is one click.
