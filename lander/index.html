Orbiter stays in orbit. Lander sets down on ordinary shared hosting: the same admin, the same SQL file (.pod), no Node and no build server.

One SQL file, two runtimes

Your content lives in a single SQL file (.pod). It is a plain SQLite database, only renamed to .pod: open it with any SQLite tool. Run it on Node with Orbiter or on PHP with Lander, and copy the file to move the whole site.

Everything an editor needs

The real admin

Station mode, themes, dock, editor and media library. Not a lookalike: the Orbiter interface, served as static files.

Live API

/api/public/<collection> with CORS and a short cache (10 s by default). Edits show on your site without a rebuild.

Markdown import

Bring in .md files with frontmatter from the admin, or with bin/lander import-md.

Media as files

Uploads go to a plain folder. File type is checked, PHP execution is blocked there.

Hardened

Server-side validation, size limits, escaped output, admin-only meta writes. The same fixes as Orbiter 0.3.92+.

Zero build

Upload a folder, point the document root at public/. No Node, no composer, no build step.

Made for phones

Dock with names, drawers as panels, lists with a “⋯” menu and swipes, big touch targets, installable on the home screen. German by default.

Music and video

Upload MP3, M4A, WAV, FLAC, OGG, MP4, WebM and MOV. Served with range requests, so Safari plays and seeks.

Preview drafts

A button opens the real page of your site for an entry, drafts included while you are signed in.
